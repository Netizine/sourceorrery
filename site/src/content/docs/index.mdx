Core, encrypted vault, CLI and read-only [SDKs](/sdks/) for Python,

## Why

We give coding agents access to repositories, terminals and build pipelines
while still distributing credentials through plaintext files that sit in the
working tree, get indexed, get pasted into prompts and get committed.
SourceOrrery takes a different line.

<CardGrid>
	<Card title="No plaintext at rest" icon="padlock">
		Every value is encrypted (XChaCha20-Poly1305) in a single SQLite file. The
		vault key is protected by your OS credential store and/or an Argon2id
		passphrase.
	</Card>
	<Card title="References, not values" icon="link">
		`sourceorrery://development/database-password` is safe to commit, log and
		paste. It resolves only inside an authorised runtime.
	</Card>
	<Card title="A manifest that cannot leak" icon="document">
		`sourceorrery.toml` declares the secrets a project needs. A `value = ...`
		key is a parse error.
	</Card>
	<Card title="Metadata by default" icon="list-format">
		`list`, `versions`, `get` and `audit` never print a value. Disclosure is a
		deliberate `get --reveal`.
	</Card>
	<Card title="Versioned and recoverable" icon="clock">
		Every `set` creates an immutable version. Deletes are soft, recoverable
		and audited. Expiry and activation times are enforced, not advisory.
	</Card>
	<Card title="One implementation" icon="seti:rust">
		The Rust core owns every semantic. Backends and language bindings pass the
		conformance suite or they are not SourceOrrery.
	</Card>
</CardGrid>

## What SourceOrrery does and does not protect

Three different guarantees, kept separate on purpose. The
[threat model](/security/threat-model/) spells out each one.

<div class="guarantees">

| Guarantee | Today |
|-----------|-------|
| **At-rest protection** — no plaintext secrets on disk, in the repo or in agent context | **Yes** |
| **Access control** — which identities may retrieve which secret | **Local only:** whoever can unlock the vault |
| **Agent isolation** — an untrusted agent running as *your* user cannot impersonate your application | **No.** Requires the authenticated broker and OS isolation (milestone 3) |

</div>

Removing `.env` closes the accidental-exposure routes. It does not stop code
running with your privileges from calling the same API you can. SourceOrrery
says so rather than promising otherwise.

## Quick start

```bash
# 1. Create a vault (key protected by the OS credential store when available)
sourceorrery vault create development

# 2. Store a secret — interactively, from stdin or a file; never as an argument
sourceorrery secret set database-password --vault development

# 3. Inspect without revealing
sourceorrery secret list --vault development
sourceorrery secret get database-password --vault development

# 4. Declare what your project needs and run it with secrets injected
sourceorrery init
sourceorrery check
sourceorrery run -- npm start      # DATABASE_PASSWORD is set in the child only
```

The [getting started](/getting-started/) page walks through each step,
starting with installing the release.
