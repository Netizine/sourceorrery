# Language bindings

Milestone 2 (shipped). The Rust core owns every semantic (ADR 0001); the
SDKs are **read-only** (ADR 0005) and each uses the most widely adopted
native-binding technology of its language (ADR 0006). The compatibility
contract is the SourceOrrery API and `sourceorrery_core::CONTRACT_VERSION`,
not any binding generator. User guides live in [`docs/sdks/`](../docs/sdks/index.md).

| Language | Directory | Technology | Package |
|----------|-----------|------------|---------|
| Rust | `crates/sourceorrery` | the client crate itself, over `sourceorrery-storage` | crates.io `sourceorrery` |
| Python | `bindings/python` | PyO3 + maturin, abi3 (3.11+) | PyPI `sourceorrery` |
| JavaScript / TypeScript | `bindings/node` | napi-rs 3, platform packages | npm `@sourceorreryai/sdk` |
| Java | `bindings/java` | Foreign Function and Memory API (22+) over the C ABI | Maven Central `ai.sourceorrery:sourceorrery` |
| .NET | `bindings/dotnet` | `LibraryImport` P/Invoke (net8.0) over the C ABI | NuGet `SourceOrrery` |
| Go | `bindings/go` | cgo over the C ABI (header vendored) | `github.com/netizine/sourceorrery/bindings/go` |
| C | `crates/sourceorrery-ffi/include`, `examples/get_secret.c` | the C ABI | the `sourceorrery-ffi-<version>-<target>` archive |
| C++ | `bindings/cpp` | header-only RAII wrapper (C++17) | the same archive |
| PHP | `bindings/php` | the FFI extension over a vendored subset of the declarations | Packagist `sourceorrery/sourceorrery` |

Every SDK exposes the same surface: open a vault with the CLI's unlock
order, get the newest accessible or an explicit version, read properties,
resolve a `sourceorrery://` reference, load a `sourceorrery.toml`, close.
Each maps `SecretError::code()` to a typed error while preserving the
code, the message and the **hint**, guards values (zeroised on close,
`[REDACTED]` when printed, not serialisable by accident), and is proven
in CI against the vault `scripts/ci/fixture-vault.sh` creates with the CLI.

## The C ABI: `crates/sourceorrery-ffi`

The crate builds a shared library, a static library and an rlib:

| Platform | Shared library | Import / static library |
|----------|----------------|-------------------------|
| Windows | `sourceorrery_ffi.dll` | `sourceorrery_ffi.dll.lib` (import), `sourceorrery_ffi.lib` (static) |
| Linux | `libsourceorrery_ffi.so` | `libsourceorrery_ffi.a` |
| macOS | `libsourceorrery_ffi.dylib` | `libsourceorrery_ffi.a` |

```bash
cargo build -p sourceorrery-ffi --release        # artefacts in target/release
cargo build -p sourceorrery-ffi --no-default-features   # no OS keyring (headless)
```

The header is `crates/sourceorrery-ffi/include/sourceorrery.h`. It is
generated by `build.rs` with cbindgen on every build of the crate,
committed, and checked in CI (`git diff --exit-code` after a build, the
`committed_header_is_current` test, and a diff against the copy vendored
in `bindings/go`). Never edit it by hand.

### Conventions

* **Strings in** are UTF-8 byte ranges `(ptr, len)`, never NUL-terminated.
  Arguments documented as nullable accept `NULL` for "absent". A `NULL`
  pointer with a non-zero length, invalid UTF-8 or malformed JSON is
  rejected with the `invalid_argument` code before anything is read.
* **Data out** is an `so_bytes { uint8_t *ptr; size_t len; }` owned by the
  caller and released with `so_bytes_free()`, which zeroises the memory
  before freeing it and resets the struct, so freeing twice is harmless.
  Every buffer carries one extra `0` byte after `len`, so JSON can be read
  as a C string. Output parameters are initialised through the raw pointer
  before a call can fail, so an uninitialised `so_bytes out;` from C is
  sound and always safe to free.
* **Metadata** (`SecretProperties`, `DeletedSecret`, `AuditEvent`,
  `VaultDescriptor`, `SetSecretOptions`, `UpdateSecretProperties`) crosses
  as JSON in the core's serde shape: `snake_case` keys, RFC 3339 timestamps,
  absent optional fields omitted. Inputs that have no serde form in the
  core are defined by the FFI crate and reject unknown fields:

  ```json
  // so_reader_open / so_project_load options_json (every field optional)
  {"home": "/path/to/home", "passphrase_file": "/run/secrets/vault", "environment": true}

  // so_vault_create options_json (every field optional)
  {"recovery_level": "recoverable", "retention_days": 90,
   "argon2": {"memory_kib": 65536, "iterations": 3, "parallelism": 1}}

  // so_audit_events query_json (every field optional)
  {"secret_name": "db-password", "operation": "secret_get",
   "since": "2026-10-20T00:00:00Z", "limit": 100}
  ```

  `argon2` tunes the passphrase protector's key derivation. Leave it unset
  outside tests; the defaults are the interactive parameters.
* **Errors**: every fallible call returns `so_status` (`SO_STATUS_OK = 0`,
  `SO_STATUS_ERROR = 1`, `SO_STATUS_PANIC = 2`). On failure the stable code
  (`SecretError::code()`: `not_found`, `version_not_found`, `deleted`,
  `deleted_conflict`, `not_deleted`, `disabled`, `not_yet_valid`,
  `expired`, `invalid_name`, `invalid_argument`, `permission_denied`,
  `locked`, `vault_not_found`, `vault_exists`, `manifest`, `crypto`,
  `storage`, `io`, `unsupported`, `migration_required`), a message and a
  **hint** (what to do about it; `NULL` when there is nothing specific to
  say) come from `so_last_error_code()`, `so_last_error_message()` and
  `so_last_error_hint()`; all three are per thread and valid until the
  next SourceOrrery call on that thread. A panic caught at the boundary
  reports the FFI-only code `internal`. Messages and hints never contain
  a value.
* **Values** cross only as raw bytes: into `so_secret_set` and out of
  `so_secret_get`, `so_reader_get`, `so_reader_resolve` and
  `so_project_entry`. The Rust copy is zeroised before the call returns;
  the caller frees its copy with `so_bytes_free` and should wipe its own
  input buffers.
* **Threads**: one reader or vault handle may be used from several threads
  at once (the vault serialises on an internal mutex). Closing a handle
  must not race with any other use of it. Read the error state on the
  thread that made the call.
* **Versioning**: `SO_ABI_VERSION` / `so_abi_version()` identify the C ABI;
  it is bumped only for incompatible changes, never for additions.
  `so_contract_version()` returns `CONTRACT_VERSION` of the core.

### Read-only functions (what SDKs link)

| C function | Client method | Notes |
|------------|---------------|-------|
| `so_reader_open(name, options_json, passphrase, out_reader)` | `SecretReader::open_with` | OS credential store, then `passphrase`, then `SOURCEORRERY_PASSPHRASE`, then the passphrase file; never a prompt |
| `so_reader_close(reader)` | drop | zeroises the vault key |
| `so_reader_descriptor(reader, out_json)` | `descriptor` | name, id, path, protectors |
| `so_reader_get(reader, name, version?, out_props, out_value)` | `get` / `get_version` | `NULL` version → newest accessible |
| `so_reader_properties(reader, name, version?, out_props)` | `properties` | no policy |
| `so_reader_resolve(reader, reference, out_props, out_value)` | `resolve` | reference must name the reader's vault |
| `so_project_load(manifest_path?, options_json, passphrase, out_project)` | `Project::load` | like `sourceorrery run` |
| `so_project_count`, `so_project_info(project, out_json)`, `so_project_entry(project, i, out_entry_json, out_value)`, `so_project_free` | `Project` accessors | entry JSON: `name`, `env`, `reference`, `required`, `properties` |
| `so_last_error_code`, `so_last_error_message`, `so_last_error_hint`, `so_last_error_clear` | — | per thread |
| `so_bytes_free` | — | zeroise + free |
| `so_abi_version`, `so_contract_version` | — | static |

### Write-capable functions (tooling only)

| C function | `SecretClient` method | Notes |
|------------|------------------------|-------|
| `so_vault_create(home, name, options_json, passphrase, out_handle)` | `VaultRegistry::create` | `passphrase == NULL` → OS-keyring protector |
| `so_vault_open(home, name, passphrase, out_handle)` | `VaultRegistry::open` | keyring first, then the passphrase once; `NULL` → keyring only |
| `so_vault_close(handle)` | drop | zeroises the vault key |
| `so_vault_descriptor(handle, out_json)` | `SqliteVault::descriptor` | name, id, backend, path, protectors |
| `so_secret_set(handle, name, value, options_json, out_props)` | `set_secret` | new immutable version |
| `so_secret_get(handle, name, version?, out_props, out_value)` | `get_secret` | `NULL` version → newest accessible |
| `so_secret_get_properties(handle, name, version?, out_props)` | `get_secret_properties` | no policy |
| `so_secret_list(handle, out_json)` | `list_properties_of_secrets` | metadata only |
| `so_secret_versions(handle, name, out_json)` | `list_properties_of_secret_versions` | newest first |
| `so_secret_update(handle, name, version?, update_json, out_props)` | `update_secret_properties` | `null` clears a field |
| `so_secret_delete(handle, name, out_deleted)` | `delete_secret` | |
| `so_secret_get_deleted(handle, name, out_deleted)` | `get_deleted_secret` | |
| `so_secret_list_deleted(handle, out_json)` | `list_deleted_secrets` | |
| `so_secret_recover(handle, name, out_props)` | `recover_deleted_secret` | |
| `so_secret_purge(handle, name)` | `purge_deleted_secret` | |
| `so_audit_events(handle, query_json, out_json)` | `audit_events` | newest first |

`home` is the SourceOrrery home directory (`NULL` or empty: `SOURCEORRERY_HOME`
or the platform data directory). Every `name`, `version`, `passphrase` and
JSON argument is a `(ptr, len)` pair; see the header for exact signatures.

### Examples

`crates/sourceorrery-ffi/examples/get_secret.c` reads a secret through the
read-only surface (the C SDK sample); `examples/smoke.c` exercises the
write-capable surface. CI compiles both with `-Wall -Wextra -Werror` and,
on Windows, `cl /W4 /WX`, and runs them. The Rust integration tests in
`crates/sourceorrery-ffi/tests` call the same exported functions and cover
the lifecycle, policy, error, hint and thread-safety behaviour.

## Adding a binding

1. Link only `so_reader_*`, `so_project_*`, `so_last_error_*` and
   `so_bytes_free` (or depend on `crates/sourceorrery` for a native
   extension).
2. Map codes to typed errors with the names the other bindings use; keep
   `code`, `message` and `hint`; never format a value.
3. Wrap values so that they are zeroised on close, print as `[REDACTED]`
   and are not serialisable by accident.
4. Write the test suite against the fixture vault
   (`scripts/ci/fixture-vault.sh` documents its contents), an example, a
   `docs/sdks/<language>.md` page, and a CI job that runs all of it on the
   three operating systems.
5. Write the conformance runner (`tests/conformance/sdk/README.md` has the
   protocol; every other binding's `conformance/` directory is a model),
   register its default command in `harness.py` and run it in the CI job.
