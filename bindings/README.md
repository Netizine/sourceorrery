# Language bindings

Milestone 2. The Rust core owns every semantic (ADR 0001); bindings expose
the `SecretClient` contract in their own language and carry no business
logic. The compatibility contract is the SourceOrrery API and
`sourceorrery_core::CONTRACT_VERSION`, not any binding generator.

| Language | Technology | Tier | Status |
|----------|------------|------|--------|
| Rust | `sourceorrery-core` + `sourceorrery-storage` crates | First-class | Shipped (milestone 1) |
| C | `sourceorrery-ffi` stable C ABI, header generated with cbindgen | First-class | **Shipped** (below) |
| C# / .NET | P/Invoke over the C ABI (`LibraryImport`) | First-class | Planned (below); blocked on a .NET 8+ SDK on the development machine |
| Python | PyO3 + Maturin wheels | First-class | Planned |
| Node.js / TypeScript | napi-rs | First-class | Planned |
| Java / Kotlin | JNI or Java FFM; UniFFI for Kotlin | First-class | Planned |
| Swift | UniFFI | First-class | Planned |
| Everything else | The C ABI or the local broker protocol (milestone 3) | Community | — |

## Contract

Every binding exposes the same surface as `sourceorrery_core::SecretClient`,
maps `SecretError::code()` to idiomatic exceptions while preserving the code,
and must pass the scenarios in `tests/conformance` through its own language.
A binding that cannot pass them does not ship.

Secret values cross the boundary as bytes with explicit length and are
zeroised on the Rust side as soon as the call returns. Bindings must offer a
scoped accessor (callback / `using` / context manager) in addition to a plain
value getter, and document that once a plaintext value is in application
memory the application can disclose it.

## The C ABI: `crates/sourceorrery-ffi`

The crate builds a shared library, a static library and an rlib:

| Platform | Shared library | Import / static library |
|----------|----------------|-------------------------|
| Windows | `sourceorrery_ffi.dll` | `sourceorrery_ffi.dll.lib` (import), `sourceorrery_ffi.lib` (static) |
| Linux | `libsourceorrery_ffi.so` | `libsourceorrery_ffi.a` |
| macOS | `libsourceorrery_ffi.dylib` | `libsourceorrery_ffi.a` |

```bash
cargo build -p sourceorrery-ffi --release        # artefacts in target/release
cargo build -p sourceorrery-ffi --no-default-features   # no OS keyring (headless)
```

The header is `crates/sourceorrery-ffi/include/sourceorrery.h`. It is
generated by `build.rs` with cbindgen on every build of the crate, committed,
and checked in CI (`git diff --exit-code` after a build, plus the
`committed_header_is_current` test). Never edit it by hand.

### Conventions

* **Strings in** are UTF-8 byte ranges `(ptr, len)`, never NUL-terminated.
  Arguments documented as nullable accept `NULL` for "absent". A `NULL`
  pointer with a non-zero length, invalid UTF-8 or malformed JSON is
  rejected with the `invalid_argument` code before anything is read.
* **Data out** is an `so_bytes { uint8_t *ptr; size_t len; }` owned by the
  caller and released with `so_bytes_free()`, which zeroises the memory
  before freeing it and resets the struct, so freeing twice is harmless.
  Every buffer carries one extra `0` byte after `len`, so JSON can be read
  as a C string. Output parameters are reset to the empty buffer before a
  call can fail, so they are always safe to free.
* **Metadata** (`SecretProperties`, `DeletedSecret`, `AuditEvent`,
  `VaultDescriptor`, `SetSecretOptions`, `UpdateSecretProperties`) crosses
  as JSON in the core's serde shape: `snake_case` keys, RFC 3339 timestamps,
  absent optional fields omitted. The two inputs that have no serde form in
  the core are defined by the FFI crate and reject unknown fields:

  ```json
  // so_vault_create options_json (every field optional)
  {"recovery_level": "recoverable", "retention_days": 90,
   "argon2": {"memory_kib": 65536, "iterations": 3, "parallelism": 1}}

  // so_audit_events query_json (every field optional)
  {"secret_name": "db-password", "operation": "secret_get",
   "since": "2026-10-20T00:00:00Z", "limit": 100}
  ```

  `argon2` tunes the passphrase protector's key derivation. Leave it unset
  outside tests; the defaults are the interactive parameters.
* **Errors**: every fallible call returns `so_status` (`SO_STATUS_OK = 0`,
  `SO_STATUS_ERROR = 1`, `SO_STATUS_PANIC = 2`). On failure the stable code
  (`SecretError::code()`: `not_found`, `version_not_found`, `deleted`,
  `deleted_conflict`, `not_deleted`, `disabled`, `not_yet_valid`,
  `expired`, `invalid_name`, `invalid_argument`, `permission_denied`,
  `locked`, `vault_not_found`, `vault_exists`, `manifest`, `crypto`,
  `storage`, `io`, `unsupported`) and a message come from
  `so_last_error_code()` / `so_last_error_message()`; both are per thread
  and valid until the next SourceOrrery call on that thread. A panic caught
  at the boundary reports the FFI-only code `internal`. Messages never
  contain a value.
* **Values** cross only as raw bytes, into `so_secret_set` and out of
  `so_secret_get`. The Rust copy is zeroised before the call returns; the
  caller frees its copy with `so_bytes_free` and should wipe its own input
  buffers.
* **Threads**: one vault handle may be used from several threads at once
  (the vault serialises on an internal mutex). Closing a handle must not
  race with any other use of it.
* **Versioning**: `SO_ABI_VERSION` / `so_abi_version()` identify the C ABI;
  it is bumped only for incompatible changes, never for additions.
  `so_contract_version()` returns `CONTRACT_VERSION` of the core.

### Functions

| C function | `SecretClient` method | Notes |
|------------|------------------------|-------|
| `so_abi_version`, `so_contract_version` | — | static |
| `so_last_error_code`, `so_last_error_message`, `so_last_error_clear` | — | per thread |
| `so_bytes_free` | — | zeroise + free |
| `so_vault_create(home, name, options_json, passphrase, out_handle)` | `VaultRegistry::create` | `passphrase == NULL` → OS-keyring protector |
| `so_vault_open(home, name, passphrase, out_handle)` | `VaultRegistry::open` | keyring first, then the passphrase once; `NULL` → keyring only |
| `so_vault_close(handle)` | drop | zeroises the vault key |
| `so_vault_descriptor(handle, out_json)` | `SqliteVault::descriptor` | name, id, backend, path, protectors |
| `so_secret_set(handle, name, value, options_json, out_props)` | `set_secret` | new immutable version |
| `so_secret_get(handle, name, version?, out_props, out_value)` | `get_secret` | `NULL` version → newest accessible |
| `so_secret_get_properties(handle, name, version?, out_props)` | `get_secret_properties` | no policy |
| `so_secret_list(handle, out_json)` | `list_properties_of_secrets` | metadata only |
| `so_secret_versions(handle, name, out_json)` | `list_properties_of_secret_versions` | newest first |
| `so_secret_update(handle, name, version?, update_json, out_props)` | `update_secret_properties` | `null` clears a field |
| `so_secret_delete(handle, name, out_deleted)` | `delete_secret` | |
| `so_secret_get_deleted(handle, name, out_deleted)` | `get_deleted_secret` | |
| `so_secret_list_deleted(handle, out_json)` | `list_deleted_secrets` | |
| `so_secret_recover(handle, name, out_props)` | `recover_deleted_secret` | |
| `so_secret_purge(handle, name)` | `purge_deleted_secret` | |
| `so_audit_events(handle, query_json, out_json)` | `audit_events` | newest first |

`home` is the SourceOrrery home directory (`NULL` or empty: `SOURCEORRERY_HOME`
or the platform data directory). Every `name`, `version`, `passphrase` and
JSON argument is a `(ptr, len)` pair; see the header for exact signatures.

### Example

`crates/sourceorrery-ffi/examples/smoke.c` creates a passphrase vault, sets
and reads a secret and checks an error code. CI compiles it with
`-Wall -Wextra -Werror` and runs it; on Windows it compiles with
`cl /W4 /WX`. The Rust integration tests in `crates/sourceorrery-ffi/tests`
call the same exported functions and cover the lifecycle, policy, error and
thread-safety behaviour.

### Interop

* `NativeMethods` is a `static partial class` with `[LibraryImport("sourceorrery_ffi")]`
  source-generated stubs (no runtime marshalling, trimming- and AOT-safe).
  Pointers are passed as `byte*` / `nuint` from pinned spans; `so_bytes` is a
  `[StructLayout(LayoutKind.Sequential)] struct { byte* Ptr; nuint Len; }`;
  `so_status` is `int`; `so_vault*` is an `IntPtr` wrapped in a
  `SafeHandle` whose `ReleaseHandle` calls `so_vault_close`.
* Strings go in as UTF-8 via `Encoding.UTF8.GetBytes` into a stack or
  pooled buffer; `null` becomes `(null, 0)`.
* `NativeLibraryLoader` registers a `DllImportResolver` on first use that
  probes `runtimes/<rid>/native/`, the directory named by
  `SOURCEORRERY_NATIVE_DIR`, and finally the default search path, mapping
  `sourceorrery_ffi` to `sourceorrery_ffi.dll` / `libsourceorrery_ffi.so` /
  `libsourceorrery_ffi.dylib`.
* On startup the library compares `so_abi_version()` with the constant it
  was compiled against and throws `SourceOrreryException("abi_mismatch")`
  on a mismatch.
* Every call: check status; on error read `so_last_error_code()` and
  `so_last_error_message()` with `Marshal.PtrToStringUTF8` immediately and
  throw through `SourceOrreryException.FromCode(code, message)`.

### Public API

```csharp
public sealed class SecretClient : IDisposable
{
    public SecretClient(string vaultName, string? passphrase = null, SecretClientOptions? options = null); // opens
    public static SecretClient CreateVault(string vaultName, string? passphrase = null, VaultCreateOptions? options = null);
    public string VaultName { get; }
    public VaultDescriptor GetVaultDescriptor();

    public SecretProperties SetSecret(string name, ReadOnlySpan<byte> value, SetSecretOptions? options = null);
    public SecretProperties SetSecret(string name, string value, SetSecretOptions? options = null);
    public Secret GetSecret(string name, string? version = null);          // Secret = (Properties, SecretValue)
    public SecretProperties GetSecretProperties(string name, string? version = null);
    public IReadOnlyList<SecretProperties> ListPropertiesOfSecrets();
    public IReadOnlyList<SecretProperties> ListPropertiesOfSecretVersions(string name);
    public SecretProperties UpdateSecretProperties(string name, string? version, UpdateSecretProperties update);
    public DeletedSecret DeleteSecret(string name);
    public DeletedSecret GetDeletedSecret(string name);
    public IReadOnlyList<DeletedSecret> ListDeletedSecrets();
    public SecretProperties RecoverDeletedSecret(string name);
    public void PurgeDeletedSecret(string name);
    public IReadOnlyList<AuditEvent> GetAuditEvents(AuditQuery? query = null);
}
```

* `SecretClientOptions { string? Home }`; `VaultCreateOptions { RecoveryLevel, int RetentionDays, Argon2Parameters? KeyDerivation, string? Home }`.
  `passphrase == null` means "use the OS credential store", matching the ABI.
* `SecretValue : IDisposable` keeps the native `so_bytes` and never copies
  it into managed memory on its own. `Use(ReadOnlySpanAction<byte, TState> action, TState state)`
  and `Use(Action<ReadOnlySpan<byte>>)` are the scoped accessors; `Length`
  is public; `CopyTo(Span<byte>)` is the plain getter; `ToString()` returns
  `"[REDACTED]"`; `Dispose()` calls `so_bytes_free` (zeroise + free) and
  is idempotent. A `string` getter is deliberately absent: .NET strings
  cannot be wiped. `Secret` is a `sealed class : IDisposable` holding
  `Properties` and `Value` and disposing the value.
* Models are `sealed record` types deserialised with a source-generated
  `JsonSerializerContext` and `JsonNamingPolicy.SnakeCaseLower`:
  `SecretProperties` (Vault, Name, Version, Enabled, ContentType, Tags,
  NotBefore, ExpiresOn, CreatedOn, UpdatedOn, RecoveryLevel),
  `DeletedSecret`, `AuditEvent` (with `Principal`), `VaultDescriptor`,
  `SetSecretOptions`, `AuditQuery`. `UpdateSecretProperties` uses an
  `Optional<T>` struct (`Unchanged` / `Clear` / `Set(value)`) with a
  converter that omits `Unchanged` and writes `null` for `Clear`, so the
  core's tri-state semantics survive. Timestamps are `DateTimeOffset`
  serialised in RFC 3339 (`"O"` is accepted by the core; outgoing values
  are normalised to UTC with second precision for readability).
* Exceptions, all deriving from `SourceOrreryException { string Code }`:

  | Code(s) | Exception |
  |---------|-----------|
  | `not_found`, `version_not_found` | `SecretNotFoundException` |
  | `disabled`, `expired`, `not_yet_valid` | `SecretPolicyException` (`IsTransient` for `not_yet_valid`) |
  | `deleted`, `deleted_conflict`, `not_deleted` | `SecretStateException` |
  | `invalid_name`, `invalid_argument` | `SourceOrreryArgumentException` |
  | `permission_denied` | `SecretAccessDeniedException` |
  | `locked` | `VaultLockedException` |
  | `vault_not_found`, `vault_exists` | `VaultException` |
  | `crypto`, `storage`, `io`, `manifest`, `unsupported`, `internal`, unknown | `SourceOrreryException` |

  Codes are append-only, so an unknown code maps to the base type and is
  never dropped.

### CI

Add to `.github/workflows/ci.yml`:

```yaml
  dotnet:
    name: .NET (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: 8.0.x
      - run: cargo build -p sourceorrery-ffi --release --locked
      - run: dotnet test bindings/dotnet/SourceOrrery.sln --configuration Release
        env:
          SOURCEORRERY_NATIVE_DIR: ${{ github.workspace }}/target/release
```

### Packaging

The `SourceOrrery` NuGet package ships the managed assembly plus
`runtimes/{win-x64,win-arm64,linux-x64,linux-arm64,osx-x64,osx-arm64}/native/`
built by the release workflow. A later `SourceOrrery.Extensions.Configuration`
package adds `AddSourceOrrery()` for `Microsoft.Extensions.Configuration`
so applications resolve `sourceorrery://` references at startup without
ever holding a `.env` file.

### Out of scope for milestone 2

Async methods (the core is synchronous until remote backends arrive in
milestone 4), protector management from .NET (use the CLI), and vault
listing or destruction (CLI).
